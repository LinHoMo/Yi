# 结论库（conclusions/）

> **这一层是什么**：把一批**固定输入**跑成静态结论快照，服务两类读者——
> **人**（审查引擎到底算出了什么：输入、复现命令、sha256 齐全，可逐字节复算）
> 与**网页版 AI**（按输入查表：命中即引用，未命中不得套用）。
>
> 555 批起本库是**唯一的结论产物层**：原 `examples/` 三份演示已并入这里（同输入、同哈希），
> 不再保留第二套入口。每条都声明自己覆盖哪个输入，未覆盖的输入一律说"未收录"。

## 目录与产物

```
conclusions/
├── INDEX.md                 # 输入 → 产物 的映射（人看 / AI 查）
├── build_conclusions.py     # 构建器：--write / --check / --selftest
├── liuyao/<id>.json/.md     # 六爻：引擎 JSON 快照 + 渲染报告
└── bazi/<id>.json/.md       # 八字：同上
```

每份报告抬头固定包含：学科、输入、复现命令、JSON 快照的相对链接与 sha256、同源复验命令、口径脚注。
`INDEX.md` 是唯一入口——**不要**让读者靠文件名猜。

## 命令

```bash
python conclusions/build_conclusions.py --write      # 生成/更新全部快照与索引
python conclusions/build_conclusions.py --check      # 逐字节复验（CI 挂此）
python conclusions/build_conclusions.py --selftest   # 7 类负例，真盘零写入
```

## 覆盖范围（先读这一条）

本库**只覆盖 `CASES` 里列出的固定输入**，不是"任意时间、任意问题都能查"。
未收录的输入有三种合规处理：

1. 本地跑引擎（命令见每条报告抬头），把输出贴给 AI；
2. 装 skills / DSH 插件，导出结构化报告；
3. 在 `CASES` 加一条、跑 `--write`、同批登记 `CHANGELOG`——这是"扩充库"的唯一方式。

**禁止**：拿库里 A 条的结论回答 B 条的问题；用样例拼一个"新盘"；把 JSON 手改成想要的结果。

## 三条铁律怎么守

- **§一.1 机械运算归代码**：所有 `.json` / `.md` 都由引擎实跑生成；构建器不写任何断语字面量，
  `--check` 逐字节比对，手改即判红。
- **§一.2 案例库隔离**：输入全是新造中性问句（`示例：…`），不触达 `data/cases/`；
  构建器不读案例库，产物里也不出现案例名。
- **§一.3 口径诚实**：每份报告带"古籍案例对齐分 ≠ 现实命中率、非预言、专业意见优先"脚注；
  不出现任何"准确率/命中率"式表述。

## 网页版 AI 怎么用

提示词模板（`outreach/WEB-AI-PROMPT.md` 第七节）给的是**查表协议**：

1. 先读 `INDEX.md`；
2. 输入与某条**完全一致** → 读该条 `.md`，按五段格式转述，注明条目 ID 与 sha256 前 8 位；
3. 不完全一致 → 说"未收录"，给本地跑法；
4. 不得用库里的样例拼新盘。

这是"AI 也能消费项目结论"的合规路径：**查表 + 转述**，不是让模型自己起卦。
