## 2026-10-10 从格判据改正 + 命宫/身宫报告修复

**口径纪律**：本轮改的是判据本身，不是门槛。基线只上抬、未下调；
未解的边界以「灰区」原文登记在函数 docstring 与本节，不写成已解决。

### 1 从格过度触发（`scripts/bazi_factors/congrge.py`）

`_from_judge` 的从弱侧守卫末项原为 `and (not day_root or strong_yinbi)`——
**与该函数自己 docstring 声明的口径相反**（原文：「有根有印比者归正格」）：
印比有力时那个 `or` 反而放行从格。实测后果是日主明明有党的命造被判从格，
而 `judge_pattern_cheng_bai` 一见从格即返回 `pattern_cheng_bai=""`（"从格/未定义格
不判成败"），《子平真诠》该造的成败救应就整段消失了。

改后口径（`有气生扶` → 不入从格）：印或比劫通根于**本气/中气**（余气不算）的支
**≥2 处**，且该支不在三合局内、不被相邻柱之冲，且该五行不遭月令克制。

逐例书证（`data/cases/bazi_classical_cases.json`，皆为原案 `source_quote` 摘句）：

| 案例 | 命造特征 | 书上 | 改前引擎 | 改后 |
|---|---|---|---|---|
| ZP004 | 己印、辛劫透且通根 | 伤官带煞透印，成格 | 从势·假从 → 无成败 | 正格论成败 |
| ZP015 | 戌戌两重本气比劫根 | 成格 | 从势 → 无成败 | 同上 |
| ZP020 | 癸禄在子（建禄格） | 成格 | 从财·真从 → 无成败 | 同上 |
| ZP029 | 卯印相于子月 | 破格 | 从官杀 → 无成败 | 同上 |
| ZC002 | 「戊土虽生犹死」 | 从财·真从 | 从财 | 仍从（春木克土，印无气） |
| ZC012 | 「紧贴相冲，运根拔尽」 | 从杀·假从 | 从 | 仍从（寅申紧贴冲拔根） |
| ZC013 | 「坐下辰土…格取从官」 | 从官 | 从 | 仍从（单处根 + 卯月克土） |

**实测读数**（`python dev_tools/check.py`）：holdout `pattern` 满分 **28/36 → 29/36**，
holdout 加权均分 **96.2% → 96.6%**；`cong_ge` **13/15 未退**，`pillars` 189/189、
`tiaohou` 19/21 不变，tune 100.0% 不变。金标准**机械层零漂移**。
基线 `DIM_HITS["holdout"]["pattern"]` 随实测 **28 → 29**（只准前进）。

**灰区（仍未解，勿当已解决）**：

1. 阈值取 ≥2 处，故**单处**有气根的正格（ZP004/ZP020/ZP029/ZP032 一类）仍有误入从格
   者；收到 1 处时 ZC009（印伏戌中）等书例反判不从。两侧不能同时满足，
   须先引入六合化气 + 透干通根的联合判据再复核。
2. 真/假从仍只认「无本气根且无有力印比」。曾试把 `from_type` 改读「任一层生扶」
   （《假从》原注「中有比劫暗生」），实测 ZC014/ZC015 回绿但 ZC001/ZC005/ZC010
   三例由真从反吐成假从，**净 −1**，故撤销该改动，原样保留。

### 2 命宫/身宫在报告里印成 Python dict（`scripts/narrate.py`）

`analyze.py` 把内核的结构体原样放进结论（`{'branch': '亥', 'ganzhi': '丁亥', 'nayin': '屋上土'}`），
`narrate.py` 直接 f-string 插值 → 报告正文出现花括号字面量。

### 3 本轮未发现缺陷的处置原则

评测 8 维中 `ten_gods / hidden_stems / shensha / dayun` 四维的**打分代码早已存在**，
失分不是判据缺陷而是**案例集里根本没有这四个 `expected` 键**（逐键计数 = 0）。

与逐例出处，不能靠跑引擎回填——故本轮不凑覆盖率，留作独立一轮（EVAL-PLAN §五 步 6）。

### 5 调候/格局冲突登记层的两个不实记载（`core/yishu_core/conflict_resolution.py`）

- **佐神分歧被整条标成「一致」**：主神落喜用而佐神落忌类时，`detail` 写明了分歧，
  但 `label` 返回「一致」，而 `analyze.py:231` 把 `label` 直接印成
  「调候格局关系：一致」——读者看摘要，分歧就丢了。现返回 `label="主神一致·佐神分歧"`，
  `conflict` 仍为 False（主神一致是本模块契约的判定点）。
- **缺数据被当成冲突**：`main_role` 映射为空（十神类无从定）时旧代码落到
  「边界情形 → conflict=True」，报告于是出现"分歧"而依据句只写着"未匹配"。
  文件头契约写的是「无调候数据 → 返回 None，不仲裁」，现按契约返回 None。

### 6 调候引文首字标点残留（`scripts/narrate.py` + `dev_tools/check.py`）

`data/tiaohou_quotes.json` 是按句切下来的片段，741 条字符串叶子里 **82 条以「，」起头**
（切片留下的，不是原文标点）。报告模板是「`）：{quote}`」，于是印成
「`）：，自有丙火…`」。

- 修在**表示层**（`narrate.py` 渲染时 `lstrip("，、。；：")`）：语料一个字没动。
  不能改数据——`build_tiaohou.py` 自述「引文逐字保留」且带
  `--check`「只比对已入库文件是否与重算一致」，改数据即破字节可复现。
- 顺带暴露并修正了 `[8] 语料接线` 的度量口径：它按 `s in out` **逐字节**判存在，
  于是这次纯粹的显示规范化把读数从 `2/302` 报成 `1/302`，把"接了线"量成"没接线"。
  现同时接受剥离首字符标点后的匹配（阈值一个没降）。实测 135 个命盘的报告
  中「：，」出现 0 次；接线门恢复 `2/302`，金标准**机械层零漂移**，
  措辞层 `e531f56d263192b2 → 28c14deba70f7f88 → d0c04afaf0a86363`。
