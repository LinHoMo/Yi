# 八字科八字 · 案例评测方案（EVAL-PLAN）

> 本文件是**方法学规范**：定死"八字科的分数怎么来、什么能评、什么不能评"。
> 落地实现见 `bazi/scripts/evaluate.py` 与 `data/cases/bazi_classical_cases.json`。
> **口径铁律**（`SKILL.md` §一.3）：本文件与评测输出中的一切分数都是**古籍案例对齐分**
> （引擎输出与古书案例要点的吻合度），用于回归审计；**不是现实预测命中率**。
> 报分必带：集合名 + n + 是否参与调参。

---

## 一、八字科评测的难处（以及这不是可以用"手感"补的坑）

命理古书的结论大多是**层次性判断**（富贵贫贱、寿夭、六亲克应），没有可比对的客观标的。拿它当"标准答案"打分，得到的数字既不可复现也不可解释——那正是铁律三要禁止的东西。

## 二、可评 / 不可评：先把尺子画在能画的地方

### 2.1 可评（答案是**离散、可枚举、书上明写**的量）

| 维度 | 标的是什么 | 为什么可评 | 古籍来源 |
|---|---|---|---|
| `pillars` | 四柱干支（年月日时） | 公历 → 干支是**历法真值**，有唯一解 | 历法（非命理） |
| `hidden_stems` | 各支藏干 | 表驱动，有通行定表 | 《三命通会·论藏干》 |
| `ten_gods` | 四柱天干对日主的十神 | 定义式，唯一解 | 《渊海子平·论十神》 |
| `dayun_direction` | 大运顺逆 | 阳年男/阴年女顺，其余逆——定义式 | 《渊海子平·论大运》 |
| `dayun_start` | 起运岁数 | 三日折一年，可算 | 《三命通会·论起运》 |
| `kong_wang` | 旬空二支 | 定义式 | 内核 |
| `shensha` | 具名神煞落支 | **起例是表**，可逐条核 | 《三命通会·神煞》 |
| `tiaohou` | 调候用神 | 《穷通宝鉴》按月令×日主给出**表**，答案是字段不是文章 | 《穷通宝鉴》 |
| `pattern_cheng_bai` | 格局成/破/救应 | 《子平真诠》给**判词式条件**（相神受伤即破格） | 《子平真诠》 |
| `cong_ge` | 从格成立与否 | 条件可枚举（有根无根、有无生扶） | 《滴天髓》 |

### 2.2 不可评（**不计分**，只作定性注记）

| 项 | 为什么不计分 |
|---|---|
| 富贵层次、社会地位 | 无客观标的；同名八字在不同时代/家庭结果不同 |
| 寿夭、疾病 | 同上；且涉及医疗，须以专业意见为准（铁律三） |
| 六亲克应（父母/配偶/子女具体际遇） | 超出可核验范围 |
| 具体吉凶年份 | 古书"果于某年"是叙述，不是可复现的标注 |
| 性情描述 | 无法离散化比对 |

> 处置：这些内容可以在案例的 `notes` 里**原文抄录**并标注 `qualitative: true`，
> **但一律不进分母**。宁可 n 小，不可混入不可核验项。

## 三、案例集规范

文件：`bazi/data/cases/bazi_classical_cases.json`

```jsonc
{
  "schema": "yi-bazi-cases/1",
  "splits": {
    "tune":    ["MX-001", "..."],   // 参与调参
    "holdout": ["MH-001", "..."]    // 永不调参
  },
  "cases": [
    {
      "id": "MX-001",
      "book": "穷通宝鉴",
      "location": "卷一·正月甲木",       // 篇名/条名，便于回查
      "source_quote": "正月甲木，丙癸并用……",  // 原文片语，逐字抄录
      "pillars": {"year": "甲子", "month": "丙寅", "day": "甲午", "hour": "庚午"},
      "gender": "男",
      "expected": {
        // 只填书上明写的量；没写的键一律不出现（不是 null，是不写）
        "tiaohou": {"main": "丙", "assist": "癸"},
        "cong_ge": false,
        "pattern": "建禄格",
        "pattern_cheng_bai": "成"
      },
      "qualitative": false,
      "notes": ""
    }
  ]
}
```

### 硬性规则

1. **只填书上明写的量**。`expected` 里**不出现**的键 = 该项对该案例 N/A，
   在统计时**从分母里剔除**——不是算错，也不是算对。
   （这是六爻 `yishu_core.eval` 已有的 strict + N/A 剔除口径，八字科沿用。）
2. **`source_quote` 必须逐字抄录原文**，不得改写、不得由现代命理书转述。
   找不到原文的案例**不入库**。
3. **一例一条出处**。同一本书的同一节可以出多例，但每例都要能指回具体条名。
4. **禁止用引擎输出反推 `expected`**。这一条是本次审计在梅花/小六壬/择吉三科
   发现的核心风险（读数 100% 说明评测集与引擎同源）；八字科从第一天就不许这么做。
   自检方法：`expected` 的每一项都要能在 `source_quote` 或该书同一节的表里找到依据。
5. **tune / holdout 一次性切分并写进文件**，此后 holdout **永不参与调参**
   （`SKILL.md` §四.1）。首版目标：tune 10 例 / holdout 10 例；不足则如实报 n。
6. **流派差异要标注**：起运折算（三日一年 vs 按节气精确到时辰）、年界（立春 vs 春节）、
   藏干权重，各家不同。案例里若涉及，在 `notes` 写明所依流派；
   **同一维度只按一种口径建期望**，不得同维度混用流派。

## 四、打分口径

### 4.1 维度与权重（总分 100）

| 维度 | 权重 | 判法 | N/A 条件 |
|---|---|---|---|
| `pillars` 四柱 | 25 | 四个干支全对才得满分，否则按对数比例 | 无（必有） |
| `ten_gods` 十神 | 15 | 四柱天干十神逐个比，按命中比例 | 无 |
| `hidden_stems` 藏干 | 10 | 四支藏干集合比对（本气必中才计该支） | 缺期望则 N/A |
| `tiaohou` 调候 | 15 | 主用神命中得 10，佐神命中再得 5 | 期望无 `tiaohou` |
| `pattern` 格局 | 10 | 格局名命中得 6，成/破/救应命中再得 4 | 期望无对应键 |
| `cong_ge` 从格 | 5 | 布尔一致即得 | 期望无 `cong_ge` |
| `shensha` 神煞 | 10 | 期望神煞集合的命中比例（多出不算错） | 期望无 `shensha` |
| `dayun` 大运 | 10 | 顺逆一致得 6；首运起运岁数误差 ≤1 岁再得 4 | 期望无 `dayun*` |

> 权重取"越靠定义式越高"的原则：四柱与十神是历法与定义，错就是错；
> 调候与格局是判据，允许流派差异但仍须可比。

### 4.2 必须同时报出的三列

每个维度报 **`hit` / `applicable` / `na`**：

```
调候用神   hit 7 / applicable 9 / na 11   (n=20)
```

**当某维度的 `applicable < 5` 时，只报命中数，不报百分比。**
当整个集合 `n < 20` 时，**总分也只报均分与极值，不报"准确率"字样**。

### 4.3 防骑墙

沿用六爻经验：凡"多选一"的维度（如调候用神、格局名），必须同时报
**候选集大小**与**随机期望基线**（例如调候主神在十干中取一，
随机期望 1/10 ≈ 10%）。只报命中率而不报基线 = 骑墙。

### 4.4 禁止事项

- ❌ 不得把 holdout 混进 tune 均分（§四.1）。
- ❌ 不得为让某个案例过关写 case-specific 分支或私有别名（§四.3）。
- ❌ 不得把 `qualitative: true` 的案例计入分母。
- ❌ 不得输出"准确率/命中率"字样；一律称**古籍案例对齐分**。

## 六、与报告层的关系

`narrate` / `render` 新增任何维度（调候、格局成败、小运流月……）时，
**评测维度与报告章节必须同名同义**，否则"算出来了但看不到"或"看到的没在评"，
两边都会慢慢失真。新增维度的提交必须同时给出：维度的古籍出处 + 评测覆盖情况 + 报告位置。
