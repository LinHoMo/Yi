# 八字科八字 · 案例评测方案（EVAL-PLAN）

> 本文件是**方法学规范**：定死"八字科的分数怎么来、什么能评、什么不能评"。
> 落地实现见 `bazi/scripts/evaluate.py` 与 `data/cases/bazi_classical_cases.json`。
> **口径铁律**（`SKILL.md` §一.3）：本文件与评测输出中的一切分数都是**古籍案例对齐分**
> （引擎输出与古书案例要点的吻合度），用于回归审计；**不是现实预测命中率**。
> 报分必带：集合名 + n + 是否参与调参。

## 二、可评 / 不可评：先把尺子画在能画的地方

### 2.1 可评（答案是**离散、可枚举、书上明写**的量）

| 维度 | 标的是什么 | 为什么可评 | 古籍来源 |
|---|---|---|---|
| `pillars` | 四柱干支（年月日时） | 公历 → 干支是**历法真值**，有唯一解 | 历法（非命理） |
| `hidden_stems` | 各支藏干 | 表驱动，有通行定表 | 出处改为**在库可回指**的两处：《千里命稿》人元篇 源L796「人元者，即地支内所藏之天干也」＋源L812／源L813（「月支内之人元属月之本气者…申月之庚」「申中暗藏戊壬」，与内核 `CANG_GAN[申]={庚,壬,戊}` 一致）、《子平真诠评注》目录 源L5「论阴阳生死（附支藏人元司令图表）」；**旧引《三命通会·论藏干》作废**——库内只有源L282「论人元司事」，那是**人元司令用事日数表**（源L283），与三元藏干是两套制度（同段「午中丙火用事七日」「子中有壬水用事七日」若当藏干用会造出 10 条伪冲突） |
| `ten_gods` | 四柱天干对日主的十神 | 定义式，唯一解 | 《渊海子平·论十神》 |
| `dayun_direction` | 大运顺逆 | 阳年男/阴年女顺，其余逆——定义式 | 《渊海子平·论大运》 |
| `dayun_start` | 起运岁数 | 三日折一年，可算 | 《三命通会·论起运》 |
| `kong_wang` | 旬空二支 | 定义式 | 内核 |
| `shensha` | 具名神煞落支 | **起例是表**，可逐条核 | 《三命通会·神煞》 |
| `tiaohou` | 调候用神 | 《穷通宝鉴》按月令×日主给出**表**，答案是字段不是文章 | 《穷通宝鉴》 |
| `pattern_cheng_bai` | 格局成/破/救应 | 《子平真诠》给**判词式条件**（相神受伤即破格） | 《子平真诠》 |
| `cong_ge` | 从格成立与否 | 条件可枚举（有根无根、有无生扶） | 《滴天髓》 |

### 2.2 不可评（**不计分**，只作定性注记）

| 项 | 为什么不计分 |
|---|---|
| 富贵层次、社会地位 | 无客观标的；同名八字在不同时代/家庭结果不同 |
| 寿夭、疾病 | 同上；且涉及医疗，须以专业意见为准（铁律三） |
| 六亲克应（父母/配偶/子女具体际遇） | 超出可核验范围 |
| 具体吉凶年份 | 古书"果于某年"是叙述，不是可复现的标注 |
| 性情描述 | 无法离散化比对 |

> 处置：这些内容可以在案例的 `notes` 里**原文抄录**并标注 `qualitative: true`，
> **但一律不进分母**。宁可 n 小，不可混入不可核验项。

## 三、案例集规范

文件：`bazi/data/cases/bazi_classical_cases.json`

```jsonc
{
  "schema": "yi-bazi-cases/1",
  "splits": {
    "tune":    ["MX-001", "..."],   // 参与调参
    "holdout": ["MH-001", "..."]    // 永不调参
  },
  "cases": [
    {
      "id": "MX-001",
      "book": "穷通宝鉴",
      "location": "卷一·正月甲木",       // 篇名/条名，便于回查
      "source_quote": "正月甲木，丙癸并用……",  // 原文片语，逐字抄录
      "pillars": {"year": "甲子", "month": "丙寅", "day": "甲午", "hour": "庚午"},
      "gender": "男",
      "expected": {
        // 只填书上明写的量；没写的键一律不出现（不是 null，是不写）
        "tiaohou": {"main": "丙", "assist": "癸"},
        "cong_ge": false,
        "pattern": "建禄格",
        "pattern_cheng_bai": "成"
      },
      "qualitative": false,
      "notes": ""
    }
  ]
}
```

### 硬性规则

1. **只填书上明写的量**。`expected` 里**不出现**的键 = 该项对该案例 N/A，
   在统计时**从分母里剔除**——不是算错，也不是算对。
   （这是六爻 `yishu_core.eval` 已有的 strict + N/A 剔除口径，八字科沿用。）
2. **`source_quote` 必须逐字抄录原文**，不得改写、不得由现代命理书转述。
   找不到原文的案例**不入库**。
3. **一例一条出处**。同一本书的同一节可以出多例，但每例都要能指回具体条名。
4. **禁止用引擎输出反推 `expected`**。这一条是本次审计在梅花/小六壬/择吉三科
   发现的核心风险（读数 100% 说明评测集与引擎同源）；八字科从第一天就不许这么做。
   自检方法：`expected` 的每一项都要能在 `source_quote` 或该书同一节的表里找到依据。
5. **tune / holdout 一次性切分并写进文件**，此后 holdout **永不参与调参**
   （`SKILL.md` §四.1）。首版目标：tune 10 例 / holdout 10 例；不足则如实报 n。
6. **流派差异要标注**：起运折算（三日一年 vs 按节气精确到时辰）、年界（立春 vs 春节）、
   藏干权重，各家不同。案例里若涉及，在 `notes` 写明所依流派；
   **同一维度只按一种口径建期望**，不得同维度混用流派。

## 四、打分口径

### 4.1 维度与权重（总分 100）

| 维度 | 权重 | 判法 | N/A 条件 |
|---|---|---|---|
| `pillars` 四柱 | 24 | 四个干支全对才得满分，否则按对数比例（每柱 6） | 无（必有） |
| `ten_gods` 十神 | 16 | 四柱天干十神逐个比，按命中比例（每位 4） | 无 |
| `hidden_stems` 藏干 | 8 | 四支藏干**本气**比对（每支 2） | 缺期望则 N/A |
| `tiaohou` 调候 | 16 | 主用神命中得 10，佐神命中再得 6 | 期望无 `tiaohou` |
| `pattern` 格局 | 12 | 格局名命中得 8，成/破/救应命中再得 4 | 期望无对应键 |
| `cong_ge` 从格 | 4 | 布尔一致即得（另有种类 1 + 真/假 1 的子项，含在格内） | 期望无 `cong_ge` |
| `shensha` 神煞 | 8 | 期望神煞集合的命中比例（多出不算错） | 期望无 `shensha` |
| `dayun` 大运 | 12 | 顺逆一致得 8；首运起运岁数误差 ≤1 岁再得 4 | 期望无 `dayun*` |

> **本表的唯一真值源是 `scripts/evaluate.py:WEIGHTS`**（该处有
> `assert sum(WEIGHTS.values()) == 100` 兜底）。2026-10-10 校正：此表原写的是
> 25/15/10/15/10/5/10/10 的初稿权重，与代码长期不一致——文档改到与代码相同，
> 不改代码（分数口径以实跑为准，`SKILL.md` 铁律三）。
>
> 权重取"越靠定义式越高"的原则：四柱与十神是历法与定义，错就是错；
> 调候与格局是判据，允许流派差异但仍须可比。

### 4.2 必须同时报出的三列

每个维度报 **`hit` / `applicable` / `na`**：

```
调候用神   hit 7 / applicable 9 / na 11   (n=20)
```

**当某维度的 `applicable < 5` 时，只报命中数，不报百分比。**
当整个集合 `n < 20` 时，**总分也只报均分与极值，不报"准确率"字样**。

### 4.3 防骑墙

沿用六爻经验：凡"多选一"的维度（如调候用神、格局名），必须同时报
**候选集大小**与**随机期望基线**（例如调候主神在十干中取一，
随机期望 1/10 ≈ 10%）。只报命中率而不报基线 = 骑墙。

### 4.4 禁止事项

- ❌ 不得把 holdout 混进 tune 均分（§四.1）。
- ❌ 不得为让某个案例过关写 case-specific 分支或私有别名（§四.3）。
- ❌ 不得把 `qualitative: true` 的案例计入分母。
- ❌ 不得输出"准确率/命中率"字样；一律称**古籍案例对齐分**。

## 六、与报告层的关系

`narrate` / `render` 新增任何维度（调候、格局成败、小运流月……）时，
**评测维度与报告章节必须同名同义**，否则"算出来了但看不到"或"看到的没在评"，
两边都会慢慢失真。新增维度的提交必须同时给出：维度的古籍出处 + 评测覆盖情况 + 报告位置。

## 七、现实反馈通道：八字侧的可测性是 0，不是"回填了 0 条"（2026-10-11 按字面实跑）

CHANGELOG 各批结尾反复写「现实反馈回填仍为 0」。这句话**自带一个前提**：存在一条通道，
只是里面还没攒到记录。前提也要跑，不能只跑数字——本仓根目录实测（三条独立可重跑）：

| 检查 | 命令（逐字） | 实测输出 |
|---|---|---|
| 事件落盘 | `ls bazi/logs` | `ls: cannot access 'bazi/logs': No such file or directory`（rc=2）；对照 `liuyao/logs/divination_events.jsonl` 2167 B ＋ `.quarantine.jsonl` |
| store／回看器 | `ls bazi/dev_tools \| grep -E 'feedback\|outcome\|event'` | 空，rc=1；六爻侧 `feedback_store.py`／`outcome.py`／`feedback_report.py` 三件齐，且 `liuyao/dev_tools/check.py:339` 真在 import 这条链 |
| 本科引用 | `grep -rn "yishu_core.feedback" bazi --include=*.py \| grep -v "^bazi/core/" \| wc -l` | **0**（2026-10-11 建通道前实测）→ **5**（2026-10-12 第一百二十五批后复跑；命中文件 `dev_tools/feedback_store.py`、`dev_tools/check_feedback.py`）。本行数字随通道建设变动，旧值保留是为说明"当时确实为 0"，不可再当现状读 |

`bazi/core/yishu_core/feedback.py` **是**存在的，很容易被当成"通道已就位"。它是共享内核的
按学科镜像，与六爻那份**字节相同**（`md5sum` 两份同为 `e5ef4d8d880960e2b5bbacfd7fe132d3`）；
实跑 introspection（`PYTHONPATH=<bazi>/core python -c "import yishu_core.feedback as F; …"`）：
`SOURCE_SYSTEMS = ('liuyao.feedback_store', 'liuyao.event_logger')`，adapter 只有
`from_liuyao_feedback` 一个，无任何以 `bazi` 命名的符号。⇒ 八字树里那份是**死副本**：
文件在，不等于本科有通道。**"文件存在"不是"它跑起来了"，更不是"它在被用"。**

⇒ 读法必须更正：八字侧的"回填 0"要读作**可测性为 0**——不是"通道空着、等样本"，
而是"通道没建、攒样本这条路不存在"。两种 0 的下一步完全不同，混起来会让
"等现实样本攒够"变成一句无法兑现的空话（本仓没有任何现实读数，一切分数只是
与古籍案例要点的一致性，见 `SKILL.md` 铁律三）。

建通道的设计约束（落地时必须**同时**满足，缺一条就宁可不做）：

- **复用 canonical schema，不另立形状**：往内核那份 `feedback.py` 增 `bazi.*` 的
  `SOURCE_SYSTEMS` 取值与 adapter；它自己的纪律是"不是平行反馈系统、不新增存储路径"。
> **状态更新（2026-10-12，第一百二十五批）**：下面这些约束已照办——通道与回验门**同批**落地
> （`dev_tools/feedback_store.py` ＋ `dev_tools/check_feedback.py` ＝门禁 `[21]`；
> 内核 `SOURCE_SYSTEMS` 增 `bazi.feedback_store`、adapter `from_bazi_feedback`，两科副本 md5 一致）。
> 于是本节顶部"回填 0"的读法要再改一次：现在**真的是"通道在、记录 0 条"**了——
> `[21]` 明报「在册 0 条／已回填现实 0 条」，并写明**可测性已从 0 变为可测，但现实证据仍为 0**。
> 结构性拦截写成了代码而非自觉：现实情形与当时断语逐字相同、或出处里出现引擎／评测／金标准／回归字样，
> `backfill()` 直接拒绝（§三.4）；判定词只取内核 `JUDGED_VALUES`（铁律一）；
> 自检一律走 `tempfile`，真实 `logs/` 从不被播种（铁律二）。

- **只登记不改判**：通道产出事后对齐读数，不回写任何历史盘的判词或分数。
- **禁止用引擎输出回填基准**（§三.4）：入册的"实际发生"只能来自人读的一手记录；
  引擎当时的结论只作为被比对的一方存着。
- **自检走临时目录**（`SKILL.md` 铁律二）：门与自检的夹具一律落 `tempfile`，
  不得往真实 `logs/` 播种。
- **措辞红线**（§四.4）：不得出现"准确率/命中率"字样，一律带样本量 `n` 与集合名，
  并按 §四.3 配随机基线。
- **判词外置**（`SKILL.md` 铁律一）：吉凶词汇进数据表，通道只搬运结构。
- **门禁同批**：通道与它的回验门一起落地——先有存储后有门，就会再多一具
  "有数据无回验"的死副本。建成前 `rule_registry` 不登记该条目（无从登记）。
