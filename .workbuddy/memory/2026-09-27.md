## 26y 轮：CI 硬化——修复 pytest 从根目录收集失败（提交待打）

- 现象：`pytest -q` 从仓库根报 4 处收集错误（zeji/meihua/xiaoliuren smoke_test 同名 basename 撞车
  + `tests/test_yingqi_windows.py` 的 `from evaluate import RHYTHM_PAIRS` 命中 zeji 那份缺常量）。
  26x 验收时我是用 `--ignore=tests/test_yingqi_windows.py` 绕开的（所以记的是 61 通过）。
- 根因：pytest 默认 `prepend` 模式把 rootdir / 被测目录塞进 sys.path；`smoke_test.py` 四科同名、
  `evaluate.py` 四科同名互相遮蔽。`smoke_test.py` 是各学科 `check.py` 子进程按路径调用的脚本，不是用例。
- 修复：`pyproject.toml` 加 `[tool.pytest.ini_options]`，`addopts="--import-mode=importlib"`
  + `testpaths=["tests"]`。纯配置、零逻辑改动；不碰任何测试/脚本。
- 验证：`python -m pytest -q` 从根 **76 passed**（与 HANDOFF 记载基线一致），test_yingqi_windows
  现正确解析到 liuyao 的 evaluate/yingqi_windows。
- 经验：仓库内同名脚本/模块多，pytest 一律走 importlib 模式 + 限定 testpaths，别用 prepend 默认。
