# Yi · 术数知识速读（面向 AI 读者）

> 本文是**给网页端大模型直接阅读的自包含知识正文**，不依赖执行代码即可回答常见的
> 六爻纳甲与八字四柱问题。判据全文见仓库 `liuyao/references/`、`bazi/references/`，
> 本篇只作导览与要点摘要；两者冲突时**以判据全文与代码输出为准**。
> 本文件由 `outreach/build_outreach.py` 拼装进根级 `KNOWLEDGE.md`，不要手改产物。

## 一、这是什么，能到什么程度

易（Yi）是一个**确定性术数排盘引擎**：六爻纳甲、八字四柱两科，各自独立、无合参层。
核心分工是「机械运算归代码，象数解读归语言模型」——起局、排盘、装卦、定宫、纳甲、
安世应、推六亲、配六神、查旬空、判旺衰、算应期、识别格局，**全部由 Python 完成**；
语言模型只负责把结构化结果讲成人话，不得自行心算或推算上述任何一项。

三段能力边界（引自 `CAPABILITY.md`，引用请连同 commit 一起引用）：

| 层 | 状态 | 含义 |
|---|---|---|
| T1 确定性排盘与推演 | 已验证 | 干支历换算、四柱、纳甲、装卦、世应、六亲、六神、旬空、六十四卦全部由代码完成 |
| T2 古籍忠实复原 | 已量化（含上限） | 所有分数是**古籍案例对齐分**，衡量引擎输出与古书要点吻合度，用于回归审计 |
| T3 现实预测能力 | 不可测、不声称 | 无任何现实结果进入评测，现实侧样本为 0 |

⚠️ **口径铁律**：仓库里出现的一切百分比都**不是预测准确率、不是命中率**。
不得脱离「集合名 + 样本量 n + 是否参与调参」单独引用数字；不得说「断事如神」「一定」。
凶象只用「偏向／有…信号／结构上」；医疗、法律、投资、重大决策必须提示以专业意见为准。

## 二、六爻纳甲（Liu Yao / 纳甲筮法）

### 2.1 一次占卜的四段流水线

```
chart（起卦·纯排盘 JSON） → analyze（结构化定性结论 JSON）
  → narrate（中文成段正文） → render（Markdown / 单文件 HTML 报告）
```

- `chart` 只出机械盘面，**不含任何吉凶断语**：问题、起卦时刻与四柱、旬空、本卦／变卦、
  六爻逐位的纳甲干支、六亲、六神、世应标记、空破标记、动变、卦辞爻辞原文。
- `analyze` 才第一次出现 `conclusion`（方向、应期、应期明细、应期窗口、信号强度、
  判定链、病药、星煞、象层等）。
- `narrate` 把结构讲成中文正文；`render` 成文交付。
- **四段不许越界**：chart 禁吉凶措辞，analyze 只出标签与数值，断语字面量外置在 `data/*.json`，
  象层只描述「有没有出象」、不参与吉凶评分。

### 2.2 起卦方式

`mode` 可取 `coin`（铜钱，可带 `seed` 复现）、`time`（时间起卦）、`number`（数字起卦，
如 `"a,b,c"`）、`manual`（六爻手动指定，如 `"7,8,9,7,6,8"`，6 老阴 7 少阳 8 少阴 9 老阳）。
同一问题不重复占卜（「再三则渎」）；要换实质角度请另起一卦（一卦一事）。

### 2.3 装卦要素

| 要素 | 说明 |
|---|---|
| 八宫 | 京房八宫（乾坎艮震巽离坤兑），每宫八卦按「本宫／一世／二世／三世／四世／五世／游魂／归魂」排 |
| 纳甲 | 天干纳卦（乾纳甲壬、坤纳乙癸等）＋地支纳爻，逐位配干支与五行 |
| 世应 | 世爻按宫变爻位定，应爻隔三位；世为自己／我方，应为对方／外部环境 |
| 六亲 | 以卦宫五行为「我」，生我者父母、同我者兄弟、克我者官鬼、我克者妻财、我生者子孙 |
| 六神 | 按日干起：青龙、朱雀、勾陈、螣蛇、白虎、玄武，自初爻向上排；只记临爻与象义，不主吉凶 |
| 旬空 | 日柱旬中空亡二支；空亡之爻待出空／冲空，月破为月支所冲之爻 |
| 动变 | 老阴老阳为动爻，动则变出之卦；化进退、回头生克、伏藏飞神皆由动变推 |

### 2.4 断卦五步（思维链）

1. **取用神**：按问句事类定用神——问财／妻看妻财，问官／病看官鬼，问文书／长辈看父母，
   问子女／医药／无忧看子孙，问同辈／朋友／竞争看兄弟；问法未命中定式时退到世爻（权宜口径）。
2. **辨旺衰**：用神得月令、得日辰、得动爻生扶为旺；逢月破、旬空、被克、入墓为衰。
3. **看动变**：原神动来生用为助力，忌神／仇神动来克泄为拖累；回头生克、化进退神、三合三刑六合六冲逐项判。
4. **参月日**：月建司一月之权、日辰司一日之权，二者对用神与动爻的生克冲合是本层主干。
5. **定应期**：按「旺者逢值逢冲、衰者待生旺、空者出空、破者实破、合者待冲、冲者待合」等阶梯排候选，
   给出**名次化候选与窗口**；窗口是结构范围提示，不等于窗口内必应。

另有「病药」（结构中偏枯处与解处）、「星煞」（只记临爻与否）、「象层」（类象、体用、卦辞爻辞、
互体、方位、六神象义）作为旁参。**象不进断**：不改 `conclusion`、不参与吉凶评分。

### 2.5 报告长什么样

一份六爻报告含「结要（问、起卦时刻、本卦变卦、结论档位、应期日历）／卦盘／正文（用神旺衰、
动变生克、病药、星煞、象上看、时间上、可以这样做）／判据所本／口径脚注」。
结论档位是**引擎档位名，不是注定断言**；细看正文的「偏向」与信号强度。

## 三、八字四柱（BaZi / Four Pillars）

### 3.1 排盘

按出生公历时刻（可带 `longitude` 做真太阳时经度校正）换算干支历，得年、月、日、时四柱。
年柱以节气（立春）为界、月柱以节为界（非农历初一），日柱由干支历连续推，时柱由日干起（五鼠遁）。
月柱由年干起（五虎遁）。每柱含天干、地支、纳音、十神；另出藏干（本气／中气／余气）、
神煞、命宫身宫、胎元、旬空。

### 3.2 判断维度

| 维度 | 说明 |
|---|---|
| 日主强弱 | 以月令为纲，参通根、透干、生扶克泄，得结构化分数与「偏强／偏弱／…」档 |
| 格局 | 月令本气十神定格（正官、七杀、正财、偏财、正印、偏印、食神、伤官等），按《子平真诠》判成败与救应 |
| 调候 | 《穷通宝鉴》月令 × 日主查表，取主调候与佐神，处理寒暖燥湿 |
| 喜用／忌神 | 由扶抑、调候、格局综合给出；结论是机械推演，不是命运断言 |
| 十神 | 比肩、劫财、食神、伤官、正财、偏财、正官、七杀、正印、偏印；古籍用字与引擎用字有映射表 |
| 大运流年 | 按性别与年干阴阳定顺逆、起运岁，逐年干支与十神对照；「行运引动」只记结构（冲提纲、入墓等），不批吉凶 |
| 神煞／病药 | 机械安星与五行偏枯提示，不批吉凶、不作医学诊断 |

### 3.3 边界

八字输出是**象征推演与方向参考，不是命运断言**；方向字段为空属正常。
疾病·体质一类只讲五行脏腑象意，明确不诊断；六亲·宫位不数人数、不断生死；
「前事验盘」用于时辰存疑时以已发生之事校准，不构成回溯断言。

## 四、术语速查（古今用字）

| 词 | 含义 |
|---|---|
| 用神 | 六爻中代表所问之事的那一爻；八字中指对命局最有益的五行／十神（两科语境不同） |
| 世爻／应爻 | 卦中我方／对方之位 |
| 原神／忌神／仇神 | 生用神者／克用神者／生忌神而克原神者 |
| 伏神／飞神 | 用神不上卦时伏藏于某爻之下，其上之爻为飞神 |
| 出空／实破 | 旬空之爻待出旬或逢冲；月破之爻待实破之期 |
| 十神 | 以日干为「我」，按五行生克与阴阳异同定的十类关系 |
| 藏干 | 地支中所藏天干，分本气／中气／余气 |
| 调候 | 依出生月令的寒暖燥湿取用神的一路判据 |
| 古籍案例对齐分 | 引擎输出与古籍案例要点的吻合度，**回归审计用，不是现实命中率** |

## 五、怎么读引擎输出 / 怎么调用

- 四个工具（1.0 API 冻结面）：`yi_liuyao`、`yi_bazi`、`yi_kb`、`yi_report`。
  前两者返回 `narrative` 正文＋结构化 `value`；`yi_kb` 返回「文件:行 + 节标题 + 摘录」；
  `yi_report` 落地 HTML/MD 报告并返回路径。
- **照 `narrative` 讲**：不要自己重算卦象、干支、纳甲、旺衰、应期；结构化字段用于补充细节。
- 知识库按篇检索，先看索引判断读哪篇，再按 `文件:行` 只读那一节，**不要整本读**。
- 从命令行复现（仓库根目录）：
  `python liuyao/scripts/chart.py --mode coin --question "某事如何" --seed 42`、
  `python bazi/scripts/chart.py --datetime "1990-05-20 12:00" --gender 男`；
  完整成文报告用两科 `scripts/render.py`。

## 六、三条铁律（对任何输出都适用）

1. **机械运算归代码**：不得心算或推算任何起局／排盘／装卦／纳甲／世应／六亲／六神／旬空／旺衰／应期／格局。
2. **案例库与解读物理隔离**：`case_library.md` 与 `data/cases/` 只服务测试运行器、用户明确要求的事后校验、
   用户主动询问「有无类似案例」三种场景；**解读交付前不得打开、不得提及案例名、不得以案例类比佐证**。
   该文件虽在 GitHub 公开，也**不得当作解读知识引用**。
3. **口径诚实**：不得把对齐分说成预测率；凶象不用「注定／一定」；重大决策提示以专业意见为准。

## 七、常见问题（可直接据此作答）

**Q：Yi 能算命吗？** 不能这样表述。它输出的是结构化排盘与条件化倾向陈述，用于参考与研究；
现实预测能力未测量、也不声称。医疗、法律、投资、重大决策请以专业意见为准。

**Q：那些百分比是什么？** 古籍案例对齐分，衡量引擎与古书要点的吻合度，用于回归审计。
引用时必须带集合名、n、是否参与调参（六爻外部集**已参与调参**，属开发集口径），
且不得改称命中率或准确率。

**Q：六爻世应怎么定？** 由卦属八宫与世变爻位机械确定，应爻与世爻隔三位；
由 `chart` 段的纳甲装卦代码给出，模型不得自行推算。八宫次序与纳支口诀见纳甲规则篇。

**Q：应期怎么算？** 由 `analyze` 段按旺衰、空破、合冲、动变等阶梯生成名次化候选与窗口，
是结构范围提示，不是「窗口内必应」。

**Q：没有装插件，网页版 AI 能用什么？** 可读本仓库的 `KNOWLEDGE.md`、`llms.txt`、
知识库判据全文与 `examples/` 里的引擎实跑示例报告；但不能现场执行 Python，
所以只能引用**已经落盘的静态结论**，不能凭空生成新盘。要现场起卦需 clone 本体或安装插件。

**Q：代码产出的结论在哪看？** `examples/liuyao-example.md` 与 `examples/bazi-example.md`
是固定输入下由四段流水线实跑生成的完整报告，含输入参数与复现命令，可用作解读范式。
另有 `examples/liuyao-time-example.md` 演示「时间起卦」这一确定性起卦方式。

**Q：六爻和八字能合着看吗？** 不能，且刻意不做。两科**相互独立、零耦合、没有合参层**：
六爻是卦象体系（六十四卦／八宫／世应），八字是干支体系（四柱／十神／大运），
机械排盘各自闭环，语言模型不得把一科的结论拿去推算另一科（铁律一：机械运算归代码）。
强行合参会引入两套体系均未验证的「互相印证」断言，违背口径诚实。需要同时了解，
请分别跑两个工具、分别读各自的判据。

**Q：知识库与对外文档多久更新一次？** 随代码批次演进。判据篇目以 `plugins/scripts/kb-docs.mjs`
为唯一真源；正文改动同批在 `DOCS.md` 登记，并过死链门（指向不存在文件即判红）与禁语门
（不得把对齐分说成预测率）。网页端请优先抓 `raw.githubusercontent.com` 直链，
`github.com/.../blob/...` 在部分联网检索通道会读不到。
