## 二、horosa-skill 值得抄的设计（→ 本仓库落点）

1. **澄清门禁（结构性，不靠提示词自律）**：凡受 时间/地点/时区/性别 影响的技法，
   参数不完整时**结构性阻断**调用，返回 `must_ask_user=true` + 可转发的澄清问题——
   「杜绝 AI 自己脑补一个生辰就开算」。
   → **落点**：`yishu_core/report/request.py` 的参数映射已做白名单校验（30d），
   下一步把「缺参报错」升级为**结构化澄清信封**（缺什么、为什么必须、该怎么问），
   并写进 `docs/AI-SOP.md`（网页 AI 深链缺参时给出可直接回给用户的追问话术）。
2. **技法出处卡（technique_card）**：每个响应声明 用了什么技法/什么流派口径/谁算的/
   版本链，声明与实际计算源不符即告警。
   → **落点**：本仓报告 meta 已带四段契约与口径，可加一块**机器可读出处块**：
   `YI_GANZHI_BOUNDARY`、`--zi-hour-type`、各科流派开关、金标准指纹、引擎版本——
   「分数口径必带集合名+n」的铁律三在报告层的延伸。
3. **忠实度基准（HorosaBench）**：非 LLM 的确定性校验器，把 AI 断言逐条分类为
   supported / invented / contradicted（对照机器可读盘面真值），106 例锁进工具注册表。
   → **落点**：本仓已有 `text_keys_selftest`（断语键一致）与 EVAL-AUDIT（评测口径审计），
   缺的是「**报告文本 vs 引擎结构化输出**」的忠实度审计——登记为待办
   （工具名建议 `tools/report_faithfulness.py`）。
4. **策略单一源 + 框架镜像**：SKILL.md 是唯一策略源，GEMINI.md/.cursor/rules 等
   全部是薄镜像。
   → 本仓 AGENTS.md/SKILL.md 已是单一源；暂**不做**镜像生成（无真实多框架需求，
   先记着）。
5. **合参纪律（hechan）**：多技法并行咨询时，结论必须绑定到具体小节；**分歧必须披露，
   严禁平均**。
   → 与 `synthesis/` 现有「时空分歧标记」同向；把「分歧披露、不平均」写成
   synthesis 的显式规则（当前是降级未参评，再进一步：并列披露分歧点）。
6. **统一信封 + 分节导出快照**：AI 读结构化小节而非自由文本；`response_view=titles`
   省上下文、完整快照留档。
   → 本仓四段契约产出本就是结构化 JSON；报告 HTML/MD 是渲染层。可借鉴其
   「AI 只取小节标题 + 按需展开」控制上下文——对 MCP `tools/mcp_router.py` 的
   返回体量有参考价值。

## 三、divination-notes-prompt 可采纳的方法论（提示词/口径层）

1. **区分「根据资料可推断」与「仅供参考的延伸判断」**——可直接写进 `docs/AI-SOP.md`
   与各科 SKILL 的叙述纪律（与铁律三「偏向/有…信号」措辞同向）。
2. **先依据后结论**：AI 叙述先列盘面依据再给判断——本仓 narrate 已带 basis 字段，
   叙述模板可再显式化（依据段在前）。
3. **反证与不确定性强制**：关键判断须带 反证/限制条件/不确定性。
4. **跨法互证**：多术数独立看同一事，用于**标记分歧**而非强行一致。
5. 注意：内容源自特定老师的讲课，**商用/转载前须核授权**；且无现成模板，
   采用的是方法论不是文本。

## 四、对新门类路线（docs/NEW-DISCIPLINES.md）的影响

- horosa-skill 的**式占类**（奇门/太乙/金口诀/大六壬）底层用的是 `kentang2017` 的
  **MIT** Python 引擎——若属实，N2（奇门）当前卡住的「起例书源」问题有了**另一条路**：
  以 MIT 上游引擎为**实现参照/交叉验证源**（不是真值源；真值源仍按仓库纪律取古籍
  原文），可显著降低「起例机械实现」的风险。
- **行动项**：核实 `kentang2017` 各引擎仓库的 LICENSE 原文与起例注释出处，再决定
  是否引入 vendor；引入的话在 `docs/NEW-DISCIPLINES.md` 增补「实现参照」小节并
  标注许可链。**未核实前不得 vendor。**

## 五、明确不采纳

- 730MB 本地运行时 + Java 星历后端：与本仓「零依赖、纯 Python、Pyodide 纯前端」
  路线冲突。
- AGPL 代码/文本：不复制（许可证传染性 vs 本仓未定开源许可）。
- 92 技法的广度优先：本仓走「少科目、深口径、可评测」路线，不追门类数量。
