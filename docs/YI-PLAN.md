# 易 · 总规划

> 版本 v0.0.1（2026-09-22）｜范围：**命·卜 两科**的统一 skill 工程｜现状：仅"卜·六爻"有实现
>
> 相科（面相、手相、堪舆）**2026-09-22 明确剔除**：不实现、不预留目录、不写占位。

## 一、定位

**易不是几个算命工具的合集，是一个"统领级 skill"。**

中国传统道数的命、相、卜不是三门独立学问，是同一套时空符号系统（阴阳·五行·干支·卦象）打在人身上的三个投影：

| | 输入 | 回答的问题 | 时间尺度 |
|---|---|---|---|
| **命** | 出生时空（四柱/紫微） | 格局与趋势：此人宜何业、何时起伏 | 一生，粗颗粒 |
| **卜** | 一念之动（六爻/梅花/小六壬） | 具体一事的成败趋向与应期 | 一事，细颗粒 |

命与卜共用同一个内核（干支历、五行、卦象、时空取数）。所以工程上的必然结论是：
**一份内核 + 若干学科适配层 + 一个合参层**。合参两科即可成立：命定趋势节律、卜决具体一事。

**终局目标（用户原话的定位）**：从多角度分别做命与卜的分析，再由"易"把它们合起来，
针对**同一个人**给出指导与规划。
这决定了本项目的差异化不在"算得准"，而在**多科结论如何对齐、冲突时如何裁决、如何落成可执行的人生建议**——这件事市面上几乎没人做。

### 学科四段契约（这是"以后加命/相不用重造轮子"的唯一保证）

每科必须且只能按此结构暴露能力：

```
chart(question, params)   → 机械起局排盘，纯确定性，输出结构化盘
analyze(chart_out)        → 规则推演：取用/旺衰/关系/格局/应期，输出因子与判据
narrate(analyze_out)      → 唯一交付正文，师傅口吻自然语言，不并列"人话/古典"两张皮
render(analyze_out)       → 交 core/report 出 HTML/MD，学科只提供盘数据与要点
```

契约稳定后，合参层只吃 `analyze_out` 的 schema，学科内部随便重构。

### 合参层的裁决规则（先定原则，M4 落实现）

1. **各守其位**：命定趋势与节律，相定禀赋与当下，卜决具体一事之趋向与应期。任何一科越位（用六爻断人一生格局、用八字断某笔钱能否当日到账）→ 判为无效输入。
2. **同向则确**：各科指向一致时，可提升陈述强度（仍不用"注定"）。
3. **异向则卜**：冲突时不平均、不取巧，回溯检查：起局时间/干支边界/用神选取是否出错（经验上分歧九成来自这三处），核对后仍分歧则如实并列两种趋向及其触发条件，交给当事人。
4. **禁止拼贴安慰叙事**：没有经文依据或卦象理据的"未来会更好"一律不写。

| 阶段 | 目标 | 交付 | 前置 |
|---|---|---|---|

## 四、验收标准（怎样算"规划落地了"）

- □ `python tools/check.py` 一条命令跑完：历法自检 + 各科契约完整性 + tune/holdout 分别出分，全绿退出码 0
- □ `core/` 内任何规则表 `grep` 不到第二份；学科目录内无断语字面量堆积
- □ 新学科（梅花）从建目录到出可评分结果 ≤ 半天工作量（证明内核抽象对了）
- □ README 有真实截图与一条可复制执行的命令；SKILL.md 与实际脚本参数、MCP 工具面一致
- □ 全仓库不出现"现实预测命中率"类宣称；每个分数带集合名与 n

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| 内核过早抽象：只有六爻一个学科时抽 core，容易抽成"六爻的形状" | M1 抽 core 的同时，M2 立刻用梅花/小六壬两个真实消费方验证；抽象不住就改 core，不允许学科另起一份表 |
| 断语/古籍文本错漏被当权威（已发现：革卦"巳日"应"己日"、34/64 卦辞截断、卦名"遯/遁"不一致） | 文本层与算法层分离，每条引文带出处与可核对标记；建 `docs/TEXTUAL-CORRECTIONS.md` 登记改动与依据 |
| 分数虚高掩盖能力不足 | 指标只作回归用；对外展示优先给"应期是否命中"这类可事后验证的硬指标 |
| 合参层沦为玄学拼贴 | 每条合参规则必须能追溯到某一科的合法结论，否则不进正文 |
| 命相铺得太早，卜科未稳 | 本规划明写 M5 才动命相，且只立骨架 |
