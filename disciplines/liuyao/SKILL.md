# 六爻占卜 Skill

> 易 v0.0.1

## ⛔ 铁律：装卦排盘必须由代码执行，LLM 禁止手动排卦

**本 skill 的核心原则是"机械运算归代码，象数解读归人"。**

> LLM 的职责限于：收集信息 → 调用排盘脚本 → 基于脚本输出解读。
>
> LLM **严禁**手动执行以下操作：
> - ❌ 手动定卦宫、排地支纳甲、定世应、推六亲、配六神、算旬空、判变卦
> - ❌ 任何"心算"排盘或"推算"替代脚本功能
>
> 上述操作**必须且只能**由 `liuyao_engine.py` 和 `classical_analysis.py` 完成。

---

## LLM 的职责是什么（铁律一的正面清单）

代码负责"算出什么卦"，LLM 负责"这卦对这个人意味着什么、以及该不该算"。具体七件事：

| # | 职责 | 为什么代码做不了 |
|---|---|---|
| 1 | **把模糊诉求变成可算输入**：所问何事、求测者性别与身份、起卦时间与时辰 | 代码不知道"她喜欢我吗"与"她是我正缘吗"是两个问题（用神层次不同） |
| 2 | **选路与核参**：选 coin/time/number/manual，传对参数；核对返回是否含 `original_hexagram`/`divination_time`/`advanced_analysis`；失败重试一次，仍失败如实报"排盘异常" | 需要理解人话与话外音 |
| 3 | **翻译判据成当事人听得懂的话**（核心价值）：把 `timing.timing_rules` 的"辰日·用神安静，逢冲之日"讲成"多半在辰日见分晓，因为用神安静、逢冲则动"；把旺衰、六神临用、六亲持世、卦身、格局详释逐条说人话 | 这是语言与语境工作，不是运算 |
| 4 | **守住一卦一事**：用户换实质角度（换用神/换层面/假设未来/比较两人）时提议另起一卦，不在原卦硬推 | 需要判断"这还算不算同一件事" |
| 5 | **分寸与措辞**：凶象说"偏向/有…信号/结构上"，不说"注定"；医疗、法律、投资一律提示以专业意见为准；不编造无判据支撑的"出路叙事" | 价值判断与责任边界 |
| 6 | **取舍与详略**：决定这次给多长、备查推演附不附、要不要出 HTML 报告 | 取决于对方的承受力与场合 |
| 7 | **事后回看**：用户反馈结果时登记对错（`logs/divination_events.jsonl`），这是唯一能产生现实效度证据的环节 | 只有对话里才有结果 |

**LLM 一律不做**：定卦宫、纳甲、安世应、推六亲、配六神、查旬空、判旺衰、算应期、识别格局、
打开案例库做类比、把对齐分说成预测率。

**这条线为什么划得这么死**：代码错是稳定的、可被看门狗抓到的；LLM 心算错是随机的、且说错了
一样自信。本仓库真实教训：爻序镜像 bug 让四处代码一致地错，正因"一致"才被评测体系长期放过——
若当初改由 LLM 手排，它可能恰好排对恒卦（记得上六动），反而让表的错误永不暴露，
同时在另外 63 卦上随机出错。**可测性优先于聪明**，所以运算归代码，判断归人。

## 核心能力

1. **多种起卦方式**：铜钱摇卦（随机模拟）、数字起卦、时间起卦、手动指定
2. **完整装卦流程**：定卦宫 → 纳甲装干支 → 安世应 → 定六亲 → 配六神 → 查空亡 → 排伏藏
3. **经典断卦八步法**：按《卜筮正宗》《增删易》之法系统化分析
4. **高级分析体系**：伏藏、暗动、月破、三合局、进神退神、反吟伏吟
5. **变卦推演**：本卦→变卦的演变路径分析

## 执行流程

### 第一步：收集信息

需要确认两项：
1. **求测问题**：用户想问的具体事项（财运、事业、感情、健康、考试、出行、诉讼、失物等）
2. **起卦方式**：默认铜钱摇卦；可提供手动结果（6 次投掷，从下往上）；可指定数字法或时间法
3. **起卦时间**：默认当前系统时间；可手动指定过去时间（如已发生事件）

不确定时主动询问，其余默认。

### 第二步：起卦

使用 `scripts/liuyao_engine.py` 排盘：

```bash
# 自动铜钱摇卦（推荐）
python <skill-path>/scripts/liuyao_engine.py --mode coin --question "用户的问题"

# 时间起卦
python <skill-path>/scripts/liuyao_engine.py --mode time --datetime "2026-09-18 14:30"

# 数字起卦（用户指定三数）
python <skill-path>/scripts/liuyao_engine.py --mode number --numbers "3,5,7"

# 手动指定六次摇卦结果（7=少阳 8=少阴 9=老阳(动) 6=老阴(动)，从下往上）
python <skill-path>/scripts/liuyao_engine.py --mode manual --yao "7,8,9,7,6,8"
```

**验证脚本输出**：必须确认返回有效 JSON，且 `original_hexagram`、`divination_time`、`advanced_analysis` 三个核心字段存在。脚本失败时重试一次；仍失败则告知用户排盘异常，**不得手动替代排盘**。

同时运行五步思维链以获得中间过程结构化数据。**此步骤不允许跳过**——LLM 不得自行手工排盘、用神选取或旺衰计算，所有象数结论以思维链 JSON 为准。

```bash
python scripts/thinking_chain.py <result_json_file>
```

需要交付报告时**一键闭环（M3.2）**，不必分步：

```bash
python scripts/yi_liuyao.py "所问之事" --when "2026-09-18 14:30" -o outputs/report.html
python scripts/yi_liuyao.py "所问之事" --mode manual --yao "7,8,9,7,6,8" -f md   # 手动起卦 / Markdown
```

内部固定 chart→analyze→render（同一份 analyze JSON 出报告，不另行断卦）；
缺省 `--mode time` 用 `--when` 时刻，不给 `--when` 用当前时刻。旧引擎入口
`liuyao_engine.py --format html --save-html` 的 HTML 分支同样走 render 单一出口。

**四段契约入口（与梅花/小六壬/择吉同构，供合参层消费）**：六爻已提供
chart→analyze→narrate→render 薄适配层，包装既有引擎、不引入新断法：

```bash
python scripts/chart.py --mode time --datetime "2026-09-18 14:30" \
       --question "用户的问题" -o scratch/chart.json      # 起卦（排盘 JSON）
python scripts/analyze.py scratch/chart.json -o scratch/analyze.json   # 推演（含 conclusion）
python scripts/narrate.py scratch/analyze.json -o scratch/正文.md      # 正文
python scripts/render.py scratch/analyze.json -o outputs/report.md     # 报告
```

analyze 输出的 `conclusion`（方向/应期/所本）与 `chart_summary`（卦名/用神/旺衰/动爻）
可直接喂 `synthesis/cli.py add-divination --analyze-json` 进合参层归一化。
narrate/render 是**薄装配**：正文一律用 `format_reading_output` 生成，不允许 LLM
在 narrate 里另起炉灶重新断卦。

历法口径默认值（改动会使断卦结果不同，非必要不动）：交节按"当日即换"（`YI_GANZHI_BOUNDARY=day`）、
夜子时不作次日（换日派需显式 `--distinguish-zi-hour --zi-hour-type late`）。

**用神的所本（禁止由 LLM 另判一遍）：** 思维链的 `step2_use_god_identification` 同时给出
`use_god_category` 与 `use_god_basis`。basis 有四种前缀，各说实话，如实转述即可：
- 「《增刪卜易》：…」——原书明写的取用法则（关系优先层，`data/rules/use_god_relations.json`，
  每条带逐字引文与偏移量可回查），或问题词典中**有引文族**的条目（会带「（问题词典·族名）」）；
- 「覆盖规则「…」·《增刪卜易》：…」——代码消歧层的命中且该层有逐字层引文
  （`data/rules/question_use_gods.json` 的 `layer_citations`，7 类）；
- 「覆盖规则「…」（消歧层，无逐字引文）」或「问题词典推断（族名·无古籍逐条出处）」——
  **没有古籍逐条出处的推断**，正文里要如实说明这是推断/消歧取法，不要伪装成古籍定论；
- 「问题词典默认（…）」——三层都未命中的兜底（默认取世爻），同样如实说明。

用神取错时不要由 LLM 心算改判（那违反铁律一，也没有可核对的产物）。缺的是信息就补信息：
求测者性别与身份会改变用神（女家占婚取官鬼、男家占婚取妻财；占夫为妻占、占妻为夫占），
`input` 里没有就把这些字段填上重跑一次，让引擎自己换到正确的法则上。
`references/interpretation_guide.md` 的用神总表用于向当事人解释"为什么取这一爻"，
不是用来另起炉灶推翻引擎。

思维链中间结果（推理链、因子贡献表）不直接照搬到正文，但解读必须基于思维链的数据和格局判定——正文是"翻译"不是"重写"。

### 第三步：综合解读（基于 JSON 直接输出正文）

**本步的目标只有一个：** 把脚本输出翻译成当事人看得懂的文字——像懂行的人当面把卦讲清楚，不要字段报表，不要第二张「人话解读」皮。

解读时参照 `references/interpretation_guide.md` 中的用神取法、旺衰规则、动变分析与应期推断，以及 `references/pattern_reference.md` 中的十二大经典格局。需要引用经典原文时，注明出处（《火珠林》/《黄金策》/《卜筮正宗》/《增删卜易》）。

#### 3.1 写作骨架

1. 接住问题，亮明结论（对于所问之事，顺 / 不稳 / 先观望）
2. 说清卦象与用神状态——旺衰译成"对这件事意味着什么"
3. 讲动变与格局时，用叙述句（谁在帮、谁在拖、古书怎么说）
4. 应期用自然语言（近日 / 窗口偏长 / 留意某几日）
5. 给 2–4 条可执行建议
6. 适度免责：医疗、法律、重大决策以专业意见为准

#### 3.2 禁止事项

- ❌ 设「人话解读」「古典解读」并列两张皮
- ❌ 把引擎 JSON 字段或评分公式原样贴进正文
- ❌ 只为「显得专业」而堆砌古奥句式

#### 3.3 核心数据读取

所有解读数据必须来自脚本输出的 JSON，路径如下：

| 需要的数据 | JSON 路径 |
|-----------|----------|
| 本卦名 / 宫 / 世代 | `original_hexagram.name` / `palace` / `generation` |
| 各爻干支、六亲、六神、动静 | `original_hexagram.yao_lines[]` |
| 世/应位置 | `yao_lines[].is_world` / `is_response`（`true` 的那条即对应） |
| 旬空 | `empty_branches[]` |
| 月建日辰干支 | `divination_time.month_stem_branch` / `day_stem_branch` |
| 动变分析（进退、合冲、三合） | `advanced_analysis.advance_retreat` / `clash_harmony` / `triple_combo` |
| 伏藏 / 暗动 / 月破 | `advanced_analysis.hidden_spirit_analysis` / `hidden_movement` / `monthly_break` |
| 变卦信息 | `changed_hexagram` |
| **主/次应期及其法则** | `thinking_chain.step5_synthesis.timing.timing_rules[]`（`{token, rule}`，第一条即主应期） |
| 应期日历日 | `thinking_chain.step5_synthesis.yingqi_dates.dates[]`（`{date, branch, rule, description}`） |
| 全部候选（仅备查） | `thinking_chain.step5_synthesis.timing.candidates_all[]`——**禁止**当作"重点应期"念给用户 |

#### 3.5 强制叙事要素（不可省略）

以下三类数据在工具输出中已结构化生成——LLM 必须将它们渲染为**自然语言叙述**，融入正文解读。每一类都有明确的作用，不能只放在"推演过程"备查中当报表处理：

| 要素 | JSON 路径 | 正文中的作用 |
|------|----------|-------------|
| 六神临用 | `thinking_chain.step5_synthesis.spirit_adjustment_reasons[]`（或在 `factor_contributions[]` 中 `name==="六神辅助"` 的 `reason` 字段） | **必须**作为判断辅助语义在正文中叙述——如"用神临勾陈，事带迟滞"，而非只说"-0.18" |
| 六亲持世 | `thinking_chain.step5_synthesis.factor_contributions[]` 中 `name==="持世"` 的 `reason` 字段（或 `classical_rule` 字段）；如思维链已生成 `scenario_interpretation` 字段，也必须在正文中反映 | **必须**将持世六亲结合当前占问语境在正文中释义——如"兄弟持世测感情，古籍云'兄动婚来必有妨'，有争竞之象" |
| 卦身 | `thinking_chain.step5_synthesis.hexagram_body_note` | **必须**作为辅助判断融入正文或结论——如"卦身临财，本在利禄"，而非只在末尾注脚 |

**示例——正确的正文叙述（含六神+六亲持世）：**

> 「卦中六亲持世为**兄弟**——占感情古籍有言'兄动婚来必有妨'，这表示感情路上存在竞争或阻力信号，不是判终散。用神上爻临**勾陈**——六神中勾陈主事缓、有牵制，配合阴日事缓，表明事情不会快速明朗，需耐心经营。」

**反例——禁止的省略写法：**

> ❌ "六神辅助：-0.18，勾陈临用阴日事缓"（只贴数字）
> ❌ "持世评分已计入"（不解释含义）
> ❌ 末尾单独一行"卦身临财"（与正文脱节）

**规则：** 三类要素在工具输出里已能完整取到（`spirit_adjustment_reasons` 已是对白化文本"勾陈临用，阴日事缓"），直接嵌入正文即可，不需要模型自己重新推理出来。

#### 3.6 [格局详释] 必须是正文的第二核心依据

`thinking_chain.step5_synthesis.reasoning_chain` 中 `[格局详释]` 段已由脚本将三刑/六冲含义/六神动爻/十二长生/伏藏等合并为一行文本，是当前数据最集中的格局源。模型在写格局分析时，**必须逐条对照此段**，将其中出现的每个要素渲染为正文：

| 格局详释要素 | 正文中必须讲什么 |
|-------------|----------------|
| 恃势之刑/无恩之刑/无礼之刑 | 待刑/已刑状态，对应"有刑伤之象，目前未全"等说明 |
| 六冲卦含义（如有） | "六冲主散/分离/速决"，但必须结合感情语境化——"非'冲散'之判，而是感情推进有变动之象" |
| 六神动爻（螣蛇临X/白虎临X 等） | 对应叙述，如"螣蛇临妻财——用爻有惊恐/变动之象" |
| 世临X（六神） | 对求测者自身的影响——如"世临勾陈——事带迟滞" |
| 十二长生（临官/帝旺/长生等） | 力量之应——如"用神临临官——力量充实，有担当之资" |

**示例**：
「格局详释提示：六冲卦（主散）、恃势之刑待刑（缺戌）、螣蛇临用神（惊恐/变动）。六冲卦占感情主'分离之象'而非终判，结合恃势之刑，感情中存在因旁人/误会造成的压力信号，戌日或戌月或能触发实质缓解。」

**禁止**：
> ❌ 只贴"格局详释"标签名，不解释其中含义
> ❌ 忽略伏藏/三刑/十二长生中任何一项，只用"格局复杂"一笔带过

### 第五步：质量自检

在交付之前逐项自检。任何一项不通过，必须修正后再交付。

- □ **排盘详表是否完整？** 必须含六亲、六神、地支、动静、旬空/月破/暗动标记（不允许只给"上X下Y卦"的文字描述，必须给出可直接对照的表格）
- □ 引用了实际卦象数据？（爻位、六亲、六神均已逐一列出）
- □ 识别了用神并说明了理由？（哪条规则 → 哪个六亲）
- □ 评估了旺衰且使用了月建和日辰？
- □ 命名了每个动爻的角色（用神/原神/忌神/仇神/闲神）和作用类型？
- □ **古典引文是否融入推理？** 判断句（"此为吉"、"事有反复"等）必须附原文出处作为佐证依据，而非仅在末尾附一句金句。
- □ 综合评分定位为"参考"？
- □ 本次解读未打开、未引用、未联想到案例库内容？
- □ 用神多现/伏藏/空亡/月破/暗动等特殊状态均已处理？
- □ 动爻分析覆盖所有动爻（无遗漏）？
- □ **应期是否给了主、次两级并说明所本法则？** 必须从 `timing.timing_rules` 取主应期与次应期，每条讲清"凭什么推出这一支"（如"用神旬空，冲空则实"），并配 `yingqi_dates.dates` 的日历日期。
- □ **有没有把候选堆成一串地支？** `candidates_all` 是备查长列表，正文只准出现主/次应期；罗列七八个地支等于没判断（旧版即如此，随机覆盖期望 92.6%，与瞎蒙无异）。
- □ **象判边界是否克制？** "象"的描述用"偏向"、"结构上"等措辞；凡终极断语必须有"此为参考"或"非确定性"标注。
- □ 正文单独读一遍：若仍像字段报表或需另一篇「翻译」才算懂，重写。

## 实践箴言——从真实交互中长出来的教训

以下内容来自真实排盘交互中的经验教训。当解读交给用户之前，先对照一遍。

### 1. 一卦一事，不要"延伸"

⛔ 第一副卦断"她是否喜欢我、未来是否有机会"——用神取世爻/妻财，这是问感情卦。
⛔ 同一个卦拿去延伸"她是不是我的正缘"——正缘是另一层问题，断法不同（男测取妻财为用，论正缘要看生合稳固、用神得力无破），不能从感情卦里硬推。

**规则：** 如果用户在第一问之后又提出实质性问题（换用神、换层面、换东西），应该另起一卦，而不是在原卦里钻牛角尖。

同类容易犯的错误：
- 感情卦里延伸"对方的家庭条件"——财爻能看对方的样貌、性格，不能直接看其家庭，要另起
- 事业卦里延伸"这个人的性格"——卦象能显示事主状态，不能直接读对方性格，要另起
- 延伸超出用神所能覆盖的领域，是跨越卦象边界的行为

### 2. 不把"象"当"判"

六爻里的象（六冲、月破、回头克、玄武…）描述的是**倾向和结构**，不是判决。

⛔ "六冲卦 = 会散" → 象，不是判
⛔ "兄弟持世 = 不是正缘" → 象，不是判
⛔ "用神月破 = 搞不定" → 象，不是判

**规则：** 在正文里描述象的时候用"偏向于"、"有…信号"、"结构上…"。不要替用户做最终的人生定论。象的方向是明确的，但未来是开放的。

### 3. 不编造"出路叙事"

⛔ "真正的正缘在散场之后才会清晰起来" ← 这句话不是从卦象里推出来的是我自己脑补的安慰话，没有原文支持。

**规则：** 如果你要加"未来会怎样"的推演，必须有经文依据（注明出处）或卦象理据（某个动变、某个合冲）。没有依据就不要画蛇添足。

### 4. 严格区分"能讲"与"不能讲"

每副卦交付之前，默念三遍：

- **能讲**：卦象里有的象（用神、旺衰、动变、格局、应期、六神辅助、特殊组合）
- **不能讲**：卦象里没有的东西（未来伴侣是谁、什么时候遇到新对象、对方家庭背景、对方心里在想什么细节、"到底成不成"的确定性断语）

跨过去一步就是主观臆测。

### 5. 关键问题另起一卦

某些问题天然应该独立起卦：

| 问法 | 为什么另起 |
|------|----------|
| "她是不是我的正缘" | 与"她喜我否"是不同层次，应期、用神、观察维度都可能不同 |
| "如果我和她分了，下一个会更好吗" | 这是"假设未来"的时态问题，第一卦不能覆盖 |
| "这个人在做什么（她在想什么）" | 这是"测人心"，不是"测事势" |
| "我和A好还是和B好" | 这是比较型问题，需要每段关系单独起卦 |

**规则：** 当用户的问题实质上换了一个角度、换了一个层次——即使措辞类似——都应该提议另起一卦。不要试图在原卦里打捞。

### 6. 结论用语控制

| 应该说的 | 不应该说的 |
|---------|----------|
| "结构偏紧，要稳住" | "她不是你的正缘" |
| "应期偏慢" | "你们散定了" |
| "卦象显示有反复" | "最终一定会怎样" |
| "当前信号偏负面" | "绝对没有希望" |
| "目前推动力不足" | "永远不可能" |

## 注意事项

1. **不应过分神化**：占卜是概率模型和象征思维的结合，给方向性建议而非确定预言。
2. **慎重对待凶象**：凶象时保持冷静，提供缓解建议。依《增删易》之法，凶中看救，绝处寻生。
3. **尊重科学**：涉及医疗、法律等重大决策时，提醒用户咨询专业意见。
4. **文化涵养**：解读兼顾《周易》哲学智慧，动静之间皆有深意。
5. **一问一卦**：同一问题不重复占卜，避免"再三则渎"。
6. **经典依归**：断卦有疑时回归四大经典——《火珠林》定其体，《黄金策》断其要，《卜筮正宗》精其法，《增删易》验其用。
