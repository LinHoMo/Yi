# 六爻书源台账（可得性与出处状态）

本文件记录**在库书源**的实测状态：每本书本地文件是什么、字节与哈希、出处文件
（`data/sources/*.provenance.json`）是否齐备、以及**哪些书在维基文库不可得**。
目的只有一个：让"这本书有没有正文""某条引文能不能核验"这类问题有据可查，
不再靠检索旁证或印象下结论。

口径（与 `AGENTS.md` 铁律二/三配套）：

- 正文只作**只读原料**进 `data/sources/`，只做字符级保存，不做任何模型转写；
- 结论只认 `action=query` 的 `missing` 字段：**限流 ≠ 不存在**，**简繁写错 ≠ 不存在**；
- 分数口径见 `docs/CHANGELOG.md`，本文件不报分。

实测时刻：**2026-10-01**。

四份正文均为 **CRLF、无 BOM**（实测）。

### sha256 口径（已消除一处"看起来不一致"）

两份早期 provenance 里的 `sha256` **与在盘文件字节的哈希不同**，原因已查明并复现：
它们是对**换行归一为 LF 的文本**取的哈希（抓取时 API 文本的原形态），而落盘脚本以
文本模式写文件，Windows 上把 `\n` 转成了 `\r\n`。两者**内容相同、字节不同**。

- `zengshan_buyi`：`sha256_lf_text` == provenance 原 `sha256` → **True**
- `huangjin_ce`：同上 → **True**

已在两份 provenance 中补 `sha256_convention` / `sha256_lf_text` / `sha256_file_bytes`
/ `eol_on_disk`，使两种口径都可复核。**今后新增书源一律按字节哈希**（`fetch_source.py`
的 `sha256` 即对落盘字节取哈希，与在盘文件一致）。

## 二、《卜筮正宗》：维基文库**没有**正文（结论，附证据）

这是本轮要处理的书源缺口。结论：**缺口性质是"未数字化"，不是"抓取失败"**，
因此**无法**用 `tools/fetch_source.py` 补齐；重复 `--force` 重抓不会得到新内容。

维基文库上《卜筮正宗》的**全部**可数字化内容 = 2 页、共 2,796 字节：

- 总页 `卜筮正宗` → 重定向至 `卜筮正宗（河潞武子龄校本）`（页面长度 912B）：只有章节目录
  （`/卷前`、`/卷01`…`/卷14`）+ PD 声明；
- `/卷前`（1,702B）：張景崧《敘》（康熙己丑），是序文，非占断正文。

总页列出的 `/卷01`–`/卷14` **全部是红链（未创建）**。四次独立探测结论一致：

| 探测方式 | 结果 |
|---|---|
| `allpages`，`apprefix=卜筮正宗` | 3 页：总页、校本总页、`/卷前` |
| `allpages`，`apprefix=…（河潞武子龄校本）/` | **1** 页：`/卷前` |
| 逐标题实测 `/卷一`…`/卷六`、`/卷01`…`/卷14` | 全部 `missingtitle` |
| 全文搜索 + `insource:"卜筮正宗"` | 命中的其余页面都是**引用**该书的文献（《增刪卜易》《黃金策》《清史稿》等），不是该书正文 |

同时实测排除了几个"换个名字就有了"的可能：`卜筮全書`、`卜筮正宗（四庫全書本）`
均为 `missingtitle`。

### 可用的那一点点：卷前《敘》

`/卷前` 是**在库可核验**的原文（出处：`data/sources/bushi_zhengzong.wikitext.txt`，
第 2 段）。其可用条目是"全书性质"的一句话，**不是占断断语**：

> 以數測而實以理斷。……是書為言數之書，而實言理之書也。
> ——《卜筮正宗》卷前·張景崧《敘》（清光緒甲辰刻本）

本条**未**写入 `data/verdicts.json` 的 `quote_database`：那张表服务于渲染层的
断语查表（`pattern → quote`），序文属"书志/口径"而非占断，放进去会污染查表语义。
需要引用时从本文件取。

### 替代路径（存在，但本轮不做）

维基文库另有《欽定古今圖書集成·博物彙編·藝術典》含**卜筮部**，是公有领域且与
《卜筮正宗》同域的汇编。但主命名空间页只是 422 字节的转写壳，正文在 `Page:`
命名空间，需要另写抽取器；且体量与《集成》其余卷次不成比例。**据此立项前先确认
目标卷次确实含所需条目**，不要凭"同域汇编"推断。

### 这个缺口卡住的是一个已立项的外部验证集

`data/cases/case_splits.json` 里**预留了 `bushi_zhengzong_holdout`，实测条目数为 0**
（同文件其余外部集：`wikisource_holdout` 35、`wikisource_direction` 36、
`yingqi_holdout` 2、`huozhulin_holdout` 2、`huozhulin_qualitative` 5；
调参集 `tune` 20、`holdout` 12）。

也就是说：**缺口不只是"少一本书"，而是让一个已立项的独立验证集无从建立**。
要立起来必须先有该书正文——而维基文库没有（§二）。在拿到可靠文本之前该 split
应保持为空，**不得用模型转写或凭印象补条目**：那会让"永不参与调参的外部集"
退化成自证（转写自洽性失败正是 `fetch_source.py` 文档里记的那类假文本）。

## 三、连带发现：`quote_database` 里 18 条《卜筮正宗》引文**在库无源可核验**

`disciplines/liuyao/data/verdicts.json` 的 `quote_database` 共 49 条，书名分布实测：

按 `source` 字段**逐字**统计（49 条，实测）：

| 书 | 条数 | 具体写法（条数） | 在库正文能否核验 |
|---|---|---|---|
| 《卜筮正宗》 | **18** | `·用神论`5 / `·归魂游魂论`2 / `·三合论`2 / `·飞伏论`2 / `·反吟伏吟论`2 / `·六合论`1 / `·六冲论`1 / `·世应论`1 / `·月破论`1 / `·暗动论`1 | **否**——本书正文不在库，维基文库也没有（见 §二） |
| 《黄金策》 | 11 | `·千金赋`8 / 无篇名1 / `·身命章`1 / `·求财章`1 | 能（`huangjin_ce.wikitext.txt`） |
| 《增删卜易》 | 17 | 无篇名10 / `·进退神论`2 / `·暗动论`2 / `·旬空论`1 / `·月破论`1 / `·飞伏论`1 | 能（`zengshan_buyi.wikitext.txt`） |
| 《火珠林》 | 2 | 均无篇名 | 能（`huozhulin.wikitext.txt`） |
| 《千金赋》 | 1 | 无篇名 | 是《黄金策》的篇，可与 `《黄金策·千金赋》`（8 条）对照定位 |

**处置：本轮不改这 18 条。** 理由有三：① 逐条判定"是否忠实于《卜筮正宗》"需要
原文，而原文不可得，任何"修正"都会变成凭印象改写，正好是铁律三要防的事；
② 实测 `QUOTE_DATABASE` 只被 `liuyao_narrate.py`（第 399 行的查表循环）使用，
是渲染期文案，不进入判定/评分（`narrative_utils.py:58` 只做一次性取值）；
③ 正确处置方式（给每条加 `verified: bool` 或 `provenance` 字段）会改动
`data/verdicts.json` 的结构，须与渲染层一起设计并重跑 golden，属独立一批的量。
**留给下一棒，本文件已把"不能核验"的事实钉住。**

### 引文出处写法粒度不一（AI 痕迹）

`source` 字段有两种粒度并存，**同一部书被拆成两组**：

- `《增删卜易》`（10 条，只写书名、无篇名）与 `《增删卜易·进退神论》`（2 条）等
  ——同书两种粒度；
- `《千金赋》`（1 条）与 `《黄金策·千金赋》`（8 条）——**同一篇两种书名写法**；
- `《黄金策》`（1 条，无篇名）与 `《黄金策·身命章》`（1 条）。

后果：任何"按 `source` 聚合计数"的脚本都会把一部书算成两本书。**同样留给下一棒**——
修它要动 `verdicts.json` 的 49 处 `source` 字面量并重跑 narrative 层指纹；
注意 `source` 会进渲染文案，统一写法会改动 golden 的 `narrate_digest`，
必须按"措辞层漂移"重新 capture 并在 `docs/CHANGELOG.md` 写明理由。

## 四、探测纪律（写给下一棒）

1. **简繁两式必须都试，且以实际式样为准**：`黄金策`（简体）存在（页面长度 65,909），
   `黃金策`（繁体）`missingtitle`；`增刪卜易`（繁体）存在，`增删卜易`（简体）
   `missingtitle`。用错式样会得出"这本书不存在"的错误结论——与"把 429 当缺失"同类。
2. **限流是状态，不是缺失**：`tools/fetch_source.py` 遇 429 按 5/15/30/60 秒退避重试，
   重试不过会明确打印"这是取不到，不是这本书不存在"。
3. **总页可能是空骨架**：维基文库不少书是"总页 + 卷次子页"，只抓总页会拿到目录。
   本工具会自动展开子页；但**子页未被创建**（红链）时，"展开后仍为空"本身就是结论，
   要像本轮一样把探测过程记下来。
4. **`fetch_source.py` 的 `CATALOG` 在 `tools/` 下**：若某书不在清单里，
   可在 `tools/scratch/` 写一个内存内补条目的驱动（复用工具自身函数，不改 `tools/`），
   本轮《卜筮正宗》就是这么抓的（`tools/scratch/fetch_bushi_zhengzong.py`）。
