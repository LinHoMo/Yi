# Yi · 术数排盘与解读

> 两个学科：**六爻（纳甲）** 与 **八字（四柱）**，互相独立、零耦合。
> 本技能只讲「怎么用工具、怎么把结果讲成人话」，**不含任何排盘算法**。

## 知识库（按需读取，别整本读）

本技能随包带 9 篇判据文档，在 `references/` 下：

- 先读 **`references/INDEX.md`** —— 它是一张「什么问题读哪一篇」的表，只有几十行。
- 常见用法：判断经典格局查 `liuyao/pattern_reference.md`（8KB，短）；
  核对纳甲规则查 `liuyao/najia_rules.md`（47KB，只在确实需要时读）；
  十神/纳音术语查 `bazi/` 下同名文件。
- **不要**为了「显得充分」把大部头通读一遍——读错一篇就白占一大块上下文。
- 懒得挑篇时，直接用 **`yi_kb`** 关键词检索：它返回「文件:行 + 节标题 + 摘录」，
  按命中位置读那一节即可。

> ⛔ 古籍案例库**刻意不在包内**。断卦时不得联想、类比或引用历史案例；
> 用户若要求「事后校验」或问「有无类似案例」，说明该能力需完整仓库环境，不要自行编造。

## ⛔ 第一铁律：机械运算归代码，象数解读归人

你**严禁**手动执行下列任何一项：

- 定卦宫、排地支纳甲、安世应、推六亲、配六神、查旬空、判旺衰、算应期、识别格局
- 任何「心算」排盘，或用「我觉得应该是」替代引擎返回

上述全部由打包的 Python 引擎完成。你只负责：**收集信息 → 调工具 → 依据输出解读**。

为什么划得这么死：代码错是稳定、可被测试抓到的；模型心算错是随机的，
而且说错了也一样自信。

## 工具

### `yi_liuyao` — 六爻纳甲

| 参数 | 说明 |
|---|---|
| `question` | 求测问题，**必填**。用用户原话，越具体越好 |
| `mode` | `coin`（铜钱摇卦，默认）／`time`（时间起卦）／`number`（三数）／`manual`（手动爻值） |
| `datetime` | 起卦时刻 `"YYYY-MM-DD HH:MM"`，缺省用当前时间 |
| `numbers` | `mode=number` 时必填，如 `"3,5,7"` |
| `yao` | `mode=manual` 时必填，6 个爻值如 `"7,8,9,7,6,8"`（6=老阴动,7=少阳,8=少阴,9=老阳动） |
| `seed` | 铜钱摇卦的随机种子，用于复现同一卦 |
| `gender` | `男`／`女`。**占感情时影响用神取法**（男占婚取妻财、女占婚取官鬼） |

### `yi_bazi` — 八字四柱

| 参数 | 说明 |
|---|---|
| `datetime` | 出生时间 `"YYYY-MM-DD HH:MM"`（公历），**必填** |
| `gender` | `男`／`女`，**必填**（大运顺逆依赖于此） |
| `longitude` | 出生地东经，用于真太阳时校正（可选） |

返回除四柱/正文外还带**结构化岁运字段**：`conclusion`（旺衰/格局/喜忌/空亡/胎元/病药）、
`dayun`（大运 8 步，含起讫岁与明动事件）、`liunian`（流年逐年明动）、`liuyue`（流月干支十神）。
讲大运流年时直接引这些字段，不要凭 narrative 复述。

**时辰不明时必须先问用户**，不可臆测——时辰错一小时，日柱/时柱与整盘结论都会变。

### `yi_kb` — 判据知识库检索（辅助）

| 参数 | 说明 |
|---|---|
| `query` | 关键词，可多个，空格分隔（如 `"用神 取法"`、`"纳甲 世应"`），**必填**；无空格的中文长词自动 2-gram 兜底，同义词自动展开（用爻↔用神、世应↔世爻/应爻、六神↔六兽） |
| `discipline` | `liuyao`／`bazi`，限定学科（缺省两科都搜） |
| `limit` | 最多返回几条（默认 5，上限 10） |

返回「文件:行 + 节标题 + 摘录」清单。**两步用法**：先 `yi_kb` 定位，再按 `file:line`
只读那一节。案例库不在检索范围（铁律二）——检索永远给不出案例内容，也不要绕道索要。

### `yi_report` — 完整排盘报告（文件）

| 参数 | 说明 |
|---|---|
| `discipline` | `liuyao`／`bazi`，**必填** |
| `format` | `html`（默认）／`md` |
| 其余 | 与对应排盘工具相同的参数（六爻带 `question` 等，八字带 `datetime`/`gender`） |

**流程**：先完成排盘与判读（yi_liuyao / yi_bazi），用户要「出报告 / 可视化 / 存档」时再调，
把返回的**文件路径**转告用户。六爻 html 与两科 md 由引擎 render 段产出；八字 html 由插件
排版层生成（文字全部来自引擎结构化字段，无新断语）。报告是判读的**呈现**，不替代判读。

## 工作流程

### 第一步：把模糊诉求变成可算输入

起卦前确认三件事：

1. **所问何事**：「最近怎么样」要问清是学业、感情、工作还是健康
2. **求测者身份与性别**：占感情、婚姻时这会直接改变用神
3. **起卦时刻**：默认当前时间；用户要占已发生的事，请其给出当时刻

不确定就问，其余用默认。**不要为了显得利落而跳过这一步**——用神取错的卦，
后面讲得再漂亮也是错的。

### 第二步：调工具

调完先看返回：

- 有没有 `original_hexagram`（六爻）／`pillars`（八字）
- `narrative` 是否为空
- 失败时工具会抛错并给出 stderr。**重试一次**；仍失败就如实告诉用户「排盘异常」，
  **不得手动替代排盘**。

### 第三步：把结果讲成人话

工具返回里有三块，各有用处：

| 返回字段 | 用途 |
|---|---|
| `narrative` | 引擎已按本仓规范写好的正文。**这是解读的主干** |
| 结构化字段（卦名/用神/旺衰/应期/四柱/格局） | 用于核对与补充，**不要原样贴给用户** |
| `key_factors` | 引擎给出的关键影响项，讲动变与格局时可引用 |

写作骨架：

1. 先接住问题、亮明结论（顺 / 不稳 / 先观望）
2. 说清卦象与用神状态——把旺衰译成「这对这件事意味着什么」
3. 讲动变与格局用叙述句：谁在帮、谁在拖
4. 应期用自然语言（近日 / 窗口偏长 / 留意某几日），**带公历日期**
5. 给 2–4 条可执行建议
6. 适度免责

**禁止**：

- ❌ 把引擎 JSON 字段或内部评分原样贴进正文（如「用神弱（1.71）」）
- ❌ 设「人话解读」「古典解读」两张皮
- ❌ 只为显得专业而堆砌古奥句式

## 一卦一事（六爻）

同一问题**不重复占卜**（再三则渎）。用户在既问之后换实质角度时，提议**另起一卦**：

| 问法 | 为什么另起 |
|---|---|
| 「她是不是我的正缘」 | 与「她喜欢我吗」层次不同，用神与应期都可能不同 |
| 「如果分了，下一个会更好吗」 | 假设未来，第一卦覆盖不了 |
| 「她心里在想什么」 | 这是测人心，不是测事势 |
| 「和 A 好还是和 B 好」 | 比较型，需各自起卦 |

不要在原来的卦里打捞。

## 边界（必须遵守）

- **不把「象」当「判」**。六冲、月破、兄弟持世、用神旬空……描述的是**倾向与结构**，
  不是判决。用「偏向」「有…信号」「结构上」，不用「注定」「一定」「绝无可能」。
- **不编造出路叙事**。「真正的正缘会在散场之后出现」这类话若没有卦象依据，一个字都不要写。
- **能讲与不能讲**：能讲卦象里有的（用神、旺衰、动变、格局、应期、六神）；
  不能讲卦象里没有的（未来伴侣是谁、对方家庭背景、对方心里的细节、成不成的确定性断语）。
- **医疗、法律、投资、重大决策**：一律提示以专业意见为准。
- **口径诚实**：引擎内的一切分数是「古籍案例对齐分」，衡量与古籍要点的吻合度，
  **不是现实命中率**。现实侧样本为零。任何情况下不得说「预测准确率 X%」。

## 八字特别注意

- 八字结论是**机械推演**：旺衰、格局名、喜用神、调候。它**不给出命运吉凶断言**，
  也不该由你补上。方向字段为空是正常的，不是缺数据。
- 大运干支是近似起运，遇到边界年份要说明这一点。
- 性别与出生时刻是硬输入，缺一不可。

## 出报告（可选）

用户要一份可读的完整报告时，六爻可另行生成 HTML/Markdown。工具本身只返回结构化结果与正文；
需要留档时把 `narrative` 与结构化字段整理成文档交付即可。
