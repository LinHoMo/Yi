# 占天候试验台协议（第一百八十批）

> **定位**：前瞻判卷闭环的第一个**客观结果任务面**——事件以小时/日计、判据取公开气象记录、
> 不依赖用户回忆与回访。本台架交付工具与协议；**真实起卦与真实在册待用户另行授权**
> （第一百七十六批重心声明：本通道属「让现实判卷」方向，非护分规则）。
> 不产引擎改动、不碰评分面：晴雨裁决表在 dev 层，引文均可回指底本。

## 一、任务定义（先冻结，后实验）

- **问题面**：单地、单日、二值断——「<地点> 于 <目标日>（当地日）降雨 / 放晴」。
- **起卦时点**：目标日前一日内任意时刻；`--datetime` 即分盘时刻，入封存的 input_sha。
- **时间窗**：`目标日..目标日`（1 日窗，窗口=事件日当天，杜绝"迟早会应"式漂移）。

## 二、客观判据（阈值先写死，不许事后调）

数据源：open-meteo Archive API（daily，当地时区）；取不到源时**降级人工**，
人工判定必须在 note 里给观测出处，不许空口。

| 断 | 判据（当日值） | 不满足 |
|---|---|---|
| 雨 | `precipitation_sum ≥ 1.0 mm` | `not_occurred` |
| 晴 | `precipitation_sum < 0.1 mm` **且** `cloud_cover_mean ≤ 30 %` | `not_occurred` |

中间态（如下雨<1mm 且多云）对任一断都是 `not_occurred`——判据完备，无"无法判"缺口；
`unverifiable` 仅留给数据源缺失日。

## 三、裁决表（书证逐字，dev 层映射）

| 盘面信号 | 断 | 所本 |
|---|---|---|
| 子孙或妻财爻独发（动） | 晴 | 《增刪卜易》源L1917「子孙为日月星斗，动则万里晴光」；源L1935「妻财天气晴明」；源L1953「占雨用父爻，占晴用子孙爻、财爻」 |
| 父母爻独发（动） | 雨 | 《增刪卜易》源L1926「父爻发动，云雾迷天，日月掩藏而雨矣」；源L1953 同条 |
| 晴雨两属同动 | **弃权** | 书无现成先后序，不强断（v0 不发明裁决；每次弃权入册成为后续立据素材） |
| 唯官鬼/兄弟动、或六爻安静 | **弃权** | 《增刪卜易》源L1980「五爻戌土鬼动，戌亥时必主黑云」书止于云象，不构成二值断；安静无发动之应（源L1953「六爻不动者，务必求其动而验之」） |

> 照录注：《增刪卜易》源L1935「财动克父而生子孙，所以主睛」——「主睛」系底本原字，照录不改（§二 照录义）。
> 旺衰参与与否从书：《增刪卜易》源L1971「所以占天时，不论旺衰」——v0 映射因此**不看**旺衰标签，
> 只看发动六亲；此点若入引擎用神层须另批带书证，本表暂留 dev 层。

## 四、登记与判卷流程

```bash
# 1) 起盘＋裁决（仅预览，不落账）
python dev_tools/tianhou.py draft --datetime "2026-10-21 15:00" --question "占天候：北京明日晴雨"

# 2) 有断则封存（经 prospective 哈希链，task=占天候；弃权不封、不落账）
python dev_tools/tianhou.py seal --chart <chart.json> --claim-target-day 2026-10-22 \
    --location 北京 --lat 39.904 --lon 116.407

# 3) 次日自动判卷（离线降级=打印人工判据与回填命令，rc=2）
python dev_tools/tianhou.py check --id <pid>

# 4) 读数（n<30 只报计数与 Wilson 区间，拒出命中率结论——铁律三）
python dev_tools/prospective.py report
```

弃权不落账但**要计数**：`tianhou.py abstain-stats` 按已跑 draft 记在临时台账，
弃权率是裁决表覆盖面的诚实读数。

## 五、已知边界（具名）

1. 单站单日二值断，样本独立性近似成立，但同城连续多日有天气自相关——攒数须跨站/跨期。
2. open-meteo 网格值≠站点实测，阈值边界日可能翻判——判据以**登记当日写死的源**为准，
   换源即改口径（新 scoring_rule_sha，旧记录自动隔离）。
3. 占天候记录走 `SCORING_RULE` v2 的 task 分支（事件定义即断语，occurred→hit），
   与极性判卷的事项记录分组不混算（report 内 task 分桶列示）。
